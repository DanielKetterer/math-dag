41. **Join two sets and count all** needs **Count out a set of a given number**? Critic: scaffold
   - Proposer's why: Step one makes a first set of a given size, such as three counters, which is counting out a set of a given number.
   - Critic: The statement and test supply the sets already built ('put 3 counters on a plate, then add 2 more'); finding the total does not need the learner to build a set of a given size. Needed when addends are given as numbers, as in the story node, where it belongs.
42. **Take objects away and count what is left** needs **Count out a set of a given number**? Critic: scaffold
   - Proposer's why: Steps one and two make the starting set and remove exactly the given number of objects, which requires counting out a given number.
   - Critic: The statement and test have the starting set and the removal supplied; counting what remains does not require counting out a given number. Needed when the amounts are given as numbers, as in the take-from story node.
43. **A count does not depend on order or arrangement** needs **The last number word in a count tells how many**? Critic: indirect (via counting.objects)
   - Proposer's why: The claim that the count stays the same under any order or arrangement is about the total named by the last word, so that idea must already be in place.
   - Critic: The invariance claim is about the number found by counting a collection; counting.objects already presupposes the last-word idea (e9), so the dependence on last-word runs through counting.objects.
44. **Compare two sets by counting** needs **A count does not depend on order or arrangement**? Critic: scaffold
   - Proposer's why: The comparison holds whatever the size or spread of the objects, because rearranging or spreading a collection does not change its count.
   - Critic: The procedure counts each set and compares the counts; it can be run without understanding that spreading or reordering leaves the number unchanged. The invariance explains why spread is irrelevant and protects against the perceptual distractor in the test, but is not a step.
45. **Share a set fairly by dealing it out** needs **Compare two sets by one-to-one matching**? Critic: scaffold
   - Proposer's why: The check that shares are equal when every recipient received an object in the last round rests on pairing objects with recipients, so unpaired objects mean unequal.
   - Critic: Dealing one at a time is executable without a check on equality; the matching idea justifies why the shares come out equal. Credit in the test is for 4 per bear made by dealing, not for the justification.
46. **Build a shape from sticks for its sides** needs **Identify and count the corners of a shape**? Critic: scaffold
   - Proposer's why: The sticks must meet end to end at the corners, so the learner must know where the corners of the goal shape come.
   - Critic: Joining sticks end to end creates the corners automatically. Knowing how many sides the shape has (e67) suffices to build it; corner knowledge helps check the figure but is not required.
47. **Take a shape apart into smaller shapes** needs **Name typical circles, squares, and triangles**? Critic: indirect (via shapes.recognize)
   - Proposer's why: The assessment asks the learner to name the smaller shapes the square splits into, such as two triangles.
   - Critic: Naming the triangles from a diagonal cut (right isosceles, turned) needs more than naming typical examples in usual orientation; the naming route runs through shapes.recognize, which itself builds on the names. Note that the test asks for naming and showing, stricter than the statement's 'or'.
